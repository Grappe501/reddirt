# Hosted DB proof after baseline

Additive schema install **adds** objects; it does not replace **hosted** read-only proof against the canonical Supabase project (**ref `giozeoqulfojhxpywjil`**).

After **Prisma migration history** is aligned and you are preparing or completing a **Netlify** production deploy, use:

- **[`post-migration-history-netlify-retry-packet.md`](./post-migration-history-netlify-retry-packet.md)** and [`data/post-migration-history-netlify-retry-packet.json`](../data/post-migration-history-netlify-retry-packet.json) — machine eligibility (no secrets).
- **[`post-migration-history-deploy-checklist.md`](./post-migration-history-deploy-checklist.md)** — operator steps immediately before retry.
- **[`data/hosted-db-proof-readiness.json`](../data/hosted-db-proof-readiness.json)** — post-deploy proof checklist (generated by `node scripts/run-hosted-db-proof-readiness.mjs`).
- **[`email-hosted-db-proof.md`](./email-hosted-db-proof.md)** — bearer `GET /api/admin/production-readiness/hosted-db` procedure.

Record proof in **operator-controlled** artifacts only: env **names** present, `SELECT 1` success, optional safe row counts — **no** voter PII export, **no** `DATABASE_URL` in chat or tickets.

**REDDIRT-HOSTED-DB-PROOF-HARDENING-1.0:** the hosted JSON now includes **`env`** ref hints (`supabaseProjectRefConfirmed`, `parseHint`) and **`productionSchemaContract`** (legacy + new public tables, **`auth.users`** presence, **`_prisma_migrations`** count vs **71**) so a passing **`ok: true`** implies the Netlify function is wired to the canonical production Supabase project ref, not merely “some Postgres.” Offline parity: **`node scripts/validate-hosted-db-proof-contract.mjs`** → [`data/hosted-db-proof-contract-validation.json`](../data/hosted-db-proof-contract-validation.json).

**REDDIRT-HOSTED-DB-PROOF-CANONICAL-FLAG-1.0:** when that contract is satisfied, **`proof.productionCanonical`** is **`true`** in the JSON (driven by read-only probes, not a separate manual toggle).
