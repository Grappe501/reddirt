## How to use this doc (and the “bar graph” convention)

Use **progress bars** on every future update so scans stay comparable:

| Symbol | Meaning |
|--------|--------|
| `█` | Done / green for production intent |
| `░` | Not done / blocked / not started |
| `▒` | Partially done / in progress / needs verification |

**Scale (10 chars):** Replace one `░` with one `█` as work completes. Example: `██████░░░░` = 60%.

**Rules for honest bars:** If hosted prod is unverified, cap at `▒` or split “code complete” vs “deployed verified.” Never mark send/import/workers as `█` unless headquarters explicitly approved that lane.

## Vision

**RedDirt** is the Kelly Grappe for Arkansas Secretary of State **campaign operating system**: public site plus admin workbench, Postgres/Prisma data, email and communications rails, organizing tools, and (in progress) **native voter contact** (text + relational reach) — **without** turning the repo into an unfenced blast tool.

**North star:** One trustworthy place for staff and volunteers to **see readiness**, **run controlled proofs** (OAuth, DB, webhooks), and **grow capability in slices** — each slice defaulting to **no live send**, **no bulk import**, **no silent automation**.

---

## Mission (what “done” means for this phase of the program)

1. **Truthful readiness** — Hosted and local diagnostics say what is actually safe to try next.  
2. **No-surprise safety** — Live email, SMS, imports, workers, and calendar writes stay **explicitly gated** until separate approvals.  
3. **Operator-first** — Plain-language admin pages for connection proof and foundation hubs; technical JSON behind bearer tokens for scripts.  
4. **Composable slices** — Small packets (validators + docs + data contracts) so AI and humans can resume without re-reading the entire repo.
