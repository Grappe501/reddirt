# P1-5 — TEST 8 STILL COLLAPSES INFORMATION INTO PERFORMANCE

The current Test 8 procedure includes:

> Show improved performance compared with appropriate component-only models.

But Test 8 is primarily an information/model-prediction question. Performance can be relevant downstream, but the architecture's canonical test asks whether system/relational variables improve prediction of system behavior beyond component-only models.

Use exactly:

### TEST 8 — WHOLE-ONLY INFORMATION

> **Does the state or relationship of the proposed whole provide reproducible task-relevant information that cannot be recovered from any single component alone and that improves prediction of system behavior beyond appropriate component-only models?**

Compact procedure:

1. Define components, boundary, task/outcome.
2. Build component-only baseline.
3. Define relational/system variables.
4. Test out-of-sample predictive improvement.
5. Perturb relational organization where possible.
6. Compare alternative boundaries/decompositions.

Required firewall:

> **WHOLE-ONLY INFORMATION IS INFORMATION IN ORGANIZATION — NOT INFORMATION FLOATING ABOVE MATTER.**

# P2-1 — `NO SINGLE PART SOLVES THE FULL PROBLEM` IS NOT REQUIRED FOR EVERY SYSTEM-LEVEL CAPABILITY

Some distributed systems may include a component capable of solving the task alone while the network improves robustness, speed, scale, or accuracy.

Do not make component incapacity a universal prerequisite.

Use:

> **The capability may depend on interactions among components rather than residing completely in any one component.**

The famous footer can remain because it states a possibility, not a universal definition:

> **THE WHOLE CAN SOLVE A PROBLEM THAT NO SINGLE COMPONENT SOLVES ALONE.**
