## 3. Why hardening was required

A prior **`data/additive-schema-clone-test-result.json`** could show **`ok: true`** and **`cloneProofPassed: true`** while **`before.publicTableCount`** was **0**, **`contactsExists`** / **`ar02VotersExists`** were false, and **`highValueProtection`** voter/legacy flags were false. That is not a **production-like** proof of additive install safety; it could mislead operators into thinking the clone path had validated warehouse preservation.

## 4. Previous false-positive clone proof

The old runner could apply additive SQL to a nearly empty DB (candidate creates many **`public`** tables), then mark success without requiring **pre-existing** high-value tables. **`recommendation.cloneProofPassed: true`** was therefore achievable without demonstrating that real campaign tables survived the apply.

## 5. New production-like clone requirements

Before **`prisma db execute`** on the clone:

| Requirement | Detail |
|-------------|--------|
| Public breadth | **`publicTableCount ≥ 100`** |
| Required `public` tables | `ar02_voters`, `contacts`, `counties`, `event_requests`, `message_audiences`, `path_to_victory`, `people`, `person_profiles` |
| Auth | **`auth.users`** exists |
| URL safety | Test URL **≠** **`DATABASE_URL`**; test Supabase ref **≠** **`giozeoqulfojhxpywjil`**; test ref **≠** **`DATABASE_URL`** ref when both are Supabase |

After apply: same tables present, **`highValueProtection`** true (including **`publicTableCountStillAdequate`**), **`productionLikeCloneProof: true`**.

## 6. Current clone proof status

With **`REDDIRT_SCHEMA_INSTALL_TEST_DATABASE_URL`** unset in automation, the clone runner writes **`configured: false`**, **`ok: false`**, **`attempted: false`**, and does not execute SQL. A **production-like fork** must be wired to the env var and the three-node script chain re-run for a green hardened artifact.

## 7. High-value data protection

**`highValueProtection`** now reflects **before → after** preservation of **`ar02_voters`**, **`contacts`**, and all required public tables, plus **`auth.users`**, and **`publicTableCountStillAdequate`**. If any drop below threshold after apply, **`cloneProofPassed`** stays false and **`nextRecommendedSlice`** steers to repair or restore slices as implemented in the runner.

## 8. Production execution review impact

**`eligibility.productionExecutionAllowed`** remains **`false`** in generated JSON. **`eligibility.cloneProofPassed`** is **`cloneProofMeaningful`** only (not raw clone JSON **`ok`** alone). **`REDDIRT-ADDITIVE-SCHEMA-PRODUCTION-EXECUTION-PACKET-1.0`** appears as **`nextRecommendedSlice`** only when validation passes and hardened clone proof is meaningful.
